## Saved state

`tests/fixtures/app_v0.ron` is generated by `write_app_v0_fixture`
(`src/app/legacy_persistence_tests.rs`) in eframe's exact file format: the `app`
value (settings, recent folders, two windows) and egui memory holding favorites,
saved searches, global and per-folder view settings, hidden-files flags and list
columns. `app_v0_fixture_loads` checks it today and must keep passing in a
migrated form.

**Constraint:** `Locations`, `SavedSearches`, `DirectoryViewSettings`,
`DirectoryShowHidden` and `ListColumns`, and every type inside them, must keep
their serde shape so saved data still imports. Their definitions can move: the
import below never relies on `TypeId`.

## Saved data is keyed by `TypeId` (pre-existing bug, now handled)

Favorites, saved searches, view settings and list columns live in egui's
persisted memory, keyed by a hash of each type's `TypeId`. A `TypeId` changes
whenever the crate or its dependencies change, so a release that changes a
dependency could not find any of them and users silently lost them. Turning the
crate into a workspace changes every `TypeId` too: `app_v0_fixture_loads` failed
for exactly this reason.

`src/legacy_import.rs` reads them independently of `TypeId`: it recomputes each
entry's key from the type hash stored in the entry (app-wide entries) or from
a folder plus that hash (per-folder entries), and tells types apart by the
fields of the value. `App::new` imports app-wide values at launch; per-folder
values are imported the first time a folder's setting is looked up. This holds
until the persistence slice replaces egui memory with the core's own versioned state.
